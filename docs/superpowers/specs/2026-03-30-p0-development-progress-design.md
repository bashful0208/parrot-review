# P0 开发进度跟踪设计

> 目标：为 P0 交付创建一个独立的开发进度跟踪文档，不改写原始范围清单。

## 设计结论

- 保留 `doc/p0-delivery-checklist.md` 作为范围基线
- 新建 `doc/p0-development-progress.md` 作为开发进度跟踪表
- 采用“阶段 + 能力域”结构
- 阶段排序基于业务依赖和实际交付先后关系
- 每个能力域下的事项细化到可直接开工或可明确验收的粒度

## 阶段划分

1. `Phase 0 基础底座`
   - 工程规范、配置校验、日志和错误体系
2. `Phase 1 多租户与核心数据模型`
   - 组织隔离、核心主数据、RLS
3. `Phase 2 仓库接入链路`
   - provider 抽象、OAuth/App 安装、Webhook
4. `Phase 3 异步审查执行链路`
   - BullMQ、worker、状态机、幂等和重试
5. `Phase 4 AI 与审查结果系统`
   - provider 工厂、统一任务接口、结果落库
6. `Phase 5 控制台交付闭环`
   - 登录、仓库页、PR 页、规则页、模型页、实时状态
7. `Phase 6 P0 增强能力`
   - 增量审查、低噪声、反馈、YAML 规则、安全、多语言、密钥安全
8. `Phase 7 测试、观测与验收`
   - 自动化测试、可观测性、P0 验收标准

## 文档规范

- 全部使用 checkbox 跟踪
- 已知完成项保留 `[x]`
- 未完成项统一使用 `[ ]`
- 每个事项尽量避免模糊表述，优先拆为字段、约束、状态、行为、展示、验收动作
