# P0 开发进度跟踪表

> 用途：本文件用于跟踪 P0 实际开发推进，不替代 `p0-delivery-checklist.md` 的范围定义。
> 原则：按业务依赖和交付先后排序；先打通闭环，再补增强能力；每项尽量细化到可直接开工或可明确验收。
>
> 当前工程基础大多已完成；数据库配置已统一收敛到自建 `PostgreSQL`：运行时通过 `DATABASE_URL` 连接，迁移目录使用 `postgres/migrations`，业务用户主体由 `app_users` 承载。Auth / Realtime / Secrets / Storage 仍是能力待定与接口预留项。

## 当前阶段建议

- 当前主线：`Phase 0 基础底座` + `Phase 1 多租户与核心数据模型`
- 前置顺序：先稳定工程规范与自建 `PostgreSQL` 数据底座及平台接口预留，再推进组织隔离、核心主数据和接入链路
- 阻塞关系：未完成数据库底座、组织隔离和核心主数据前，不进入完整 PR 自动审查闭环开发
- 开发节奏：工程基础大多已完成，当前优先补齐数据库主链路与平台能力预留，再推进“可运行链路”和后续增强
